# Final Information Architecture

| Page group | Purpose and intent | Primary action | Indexation |
|---|---|---|---|
| `/` | Establish category, differentiation, proof and routes to support. | Contact TenderLab / choose support. | Index |
| `/services` | Compare service options by the work in front of the buyer. | Select a service. | Index |
| `/services/bid-viability` | Decide whether a live opportunity appears suitable before committing. | Share tender documents. | Index |
| `/services/bid-writing` | Explain end-to-end specialist care tender writing. | Discuss the live tender. | Index |
| `/services/pre-submission-review` | Explain independent review of an existing draft. | Request a review. | Index |
| `/services/lost-bid-debrief` | Explain post-award feedback analysis and reusable learning. | Share feedback. | Index |
| `/services/tender-readiness-audit` | Explain evidence and capability preparation before a target tender. | Assess readiness. | Index |
| `/services/tender-training` | Explain practical internal bid-team training. | Discuss training. | Index |
| `/services/retainer` | Explain ongoing pipeline, evidence and bid support. | Discuss ongoing support. | Index |
| `/care-settings` | Help users find sector-specific procurement guidance. | Choose a care setting. | Index |
| `/care-settings/[slug]` | Satisfy genuine service-setting intent with distinct content and relevant tenders. | Discuss this type of tender. | Index when substantive |
| `/tenders` | Search and filter live public-sector care opportunities. | View a tender. | Index |
| `/tenders/[slug]` | Present official tender details, source and a contextual enquiry route. | Ask about this tender. | Index while useful; expiry handling defined |
| `/case-studies` | Present inspectable, appropriately redacted evidence. | Open case study. | Index |
| `/case-studies/[slug]` | Explain starting point, procurement, TenderLab role and documented result. | Discuss a similar requirement. | Index |
| `/blog` | Browse useful care tender guidance. | Read an article. | Index |
| `/blog/[slug]` | Answer a defined informational or decision-support query. | Continue to relevant service/tender. | Index when substantive |
| `/guides` and decision guides | Answer pricing, comparison, readiness and problem queries not served elsewhere. | Choose next step. | Index selectively |
| `/about` | Establish legitimacy, positioning, method and verified proof. | Contact TenderLab. | Index |
| `/reviews` | Present verified independent feedback and source links. | Read proof / contact. | Index |
| `/faqs` | Answer recurring buyer questions with links to authoritative pages. | Follow relevant route. | Index if non-duplicative |
| `/contact` | Provide accessible contextual enquiry, phone, email, registered office and next steps. | Send enquiry. | Index |
| `/privacy-policy`, `/terms` | Meet legal and trust needs. | None. | Index/canonical self |

The footer groups Support, Care settings, Proof, Company and Independent profiles. It must remain light, consistent and concise.
